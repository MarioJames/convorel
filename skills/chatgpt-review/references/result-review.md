# 开发完成后的结果校验

在一项具有明确架构约束或模块边界的功能完成、本地必要验证通过后，交付前默认做一次结果校验；用户显式要求时也适用。普通文案、样式及沿用既有模式的小修正不自动增加远端审查。目的是判断实际结果是否解决了原问题、架构是否合理以及有无偏移，不默认转成逐文件代码审计。

## 准备结果说明

用已有任务记录组织一份简短材料，不另建方案管理系统：

- 原目标、范围、已确认的架构约束，以及明确不做的内容。没有既定方案时以用户目标和已有约束为准，不补造“原方案”。
- 最终行为及主要模块的职责、依赖方向或数据流；必要入口与文档用 `文件路径:起始行-结束行` 引用，并说明待核实的问题，由 MCP 按需读取。只描述与本次交付相关的变化，不粘贴仓库源码或完整 diff。
- 对照约束说明实际变化、主动调整及理由，区分用户已同意的调整和仍未确认的偏移。
- 必要的基线/目标 revision 与未提交修改范围（工作区由任务绑定自动提供）；本地验证摘要、已知限制和未解决问题。通常不需要完整日志或源码。

在请求中明确采用**结果校验**视角，请 ChatGPT 判断：目标是否实现，职责边界、依赖和数据流是否合理，是否遗漏重要约束或增加不必要的复杂度。优先依据上述说明；有具体疑点时直接核实相关引用、架构文档或关键入口，避免无目的地展开所有文件。目录结构本身不证明实际依赖方向或运行行为。

要求给出“符合目标 / 存在偏移 / 证据不足”的判断及依据；偏移需说明对应原约束、实际结果、影响和最小修正。将已验证问题、待确认风险和可选建议分开。若只能依据本地 Agent 的说明判断，明确证据限制；不得把模型赞同当成本地验收通过。

## 续谈与收尾

复用同一需求的 Convorel 会话，已有适用于当前交付版本的结果校验则直接使用。方案审查判断的是拟议设计，不能代替实现完成后的对照；最终实现是本轮的新证据。修复实现审查指出的问题时，请 ChatGPT 对精确交付 revision 明确回答“通过 / 未通过 / 证据不足”。只有明确通过且本地 Agent 已核对依据，才结束该修复的复审；未通过或证据不足就针对实质问题继续修复、验证或补证，并在同一会话续谈。普通结果校验通常只做一次，不为可选建议反复求批准。

本地 Agent 核对意见，记录采纳或拒绝的理由。已确认的范围内问题在交付前修正并做相关验证；需要改变用户目标或范围的决定交给用户。随后按现有 Convorel 流程保存结果、命名并释放自有页面。结果校验不能代替测试，也不授权自动发布、扩大代码访问或执行任意宿主命令。

## 按需核实证据

通用工具发现、工作区定位、版本与分页、产物和记忆使用由 Convorel 自动提供，不在审查请求中重复命令手册。证据选择服务于本次结果校验：已提交结果注明基线和目标 revision，未提交结果说明工作树范围；工作区干净不代表最近没有更新。

本地验证摘要注明执行版本、命令、时间、结果及限制。有具体疑点再提供相关报告、日志片段或截图引用，不默认发送完整日志或开放私有任务状态。区分实际观察、本地 Agent 的验证报告和推断；隔离环境缺少网络、环境文件或依赖造成的失败不能直接归因于产品缺陷。记忆只辅助核对先前决策，不替代当前版本证据。
